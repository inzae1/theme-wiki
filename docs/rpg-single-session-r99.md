# 단일 접속권과 계정 통합

계정별 서버 접속권 하나만 유지한다. 페이지마다 별도 무작위 토큰을 만들고 로그인 JWT와 함께 확인한다. 6초 주기 확인, 30초 만료를 사용하며 명시적인 이 기기에서 이어하기로만 살아 있는 다른 접속권을 넘겨받는다. 넘겨받기에는 최신 클라우드 진행을 불러온다. 같은 브라우저는 BroadcastChannel로 기존 화면을 즉시 멈추고 다른 기기는 다음 확인에서 멈춘다. 서버는 즉시 예전 접속권의 쓰기를 거부한다.

클라우드 저장·랭킹 갱신·레이드·융합은 서버에서 접속권을 검사한다. 클라우드 테이블 직접 쓰기는 차단한다. 게스트는 구글 로그아웃 후 기기에만 저장하며, 이미 클라우드 저장이 있는 계정에는 게스트 진행을 덮어쓸 수 없다. 새 계정의 최초 게스트 연결은 지원한다. 익명 상태에서 여러 오프라인 창을 여는 것 자체를 식별하는 장치는 아니며, 해당 진행의 기존 계정 재업로드·온라인 보상 경로를 차단한다.

오프라인 보상은 접속권 획득 때 서버가 계산한 한 번의 시간만 사용하며 반복 불러오기로 중복 지급하지 않는다. 네트워크 확인 실패·접속권 분실 시 진행과 로컬 저장을 멈추고 이어하기 또는 게스트 선택 화면을 연다.

## 안전한 적용 순서

1. sessions.sql 설치: 기존 강제 적용 상태는 유지하며 최초 설치는 enforced=false.
2. JS/Postgres 전용 검사와 운영 롤백 검증 실행.
3. 새 클라이언트 배포·확인.
4. 운영자가 검토한 통합 SQL에서 원본을 비공개 테이블에 백업하고 주 계정에 캐릭터별 전체 저장을 선택해 이전한다. 중복 재화를 합산하지 않는다. 원본 계정과 저장은 삭제하지 않는다.
5. 이전 계정 쓰기·레이드 차단, 랭킹 제외, 기존 접속권 만료 및 enforced=true를 같은 트랜잭션에서 적용한다.

계정별 실제 ID를 넣은 운영 통합 SQL과 원본 백업은 공개 저장소에 포함하지 않는다. merge-accounts.template.sql은 가상 ID를 쓰는 검토용 템플릿이다. 되돌리기는 비공개 merge_backups의 원본과 revision 검사를 사용한다.

## 검사

verify-rpg-play-session, verify-rpg-account, verify-rpg-conflict, raid-test/verify-sessions, raid-test/verify-account-merge 통과. 운영 DB에서도 실제 authenticated 역할로 획득·저장·중복 차단·넘겨받기·예전 토큰/구형 쓰기 거부·신규 토큰 저장·레이드 복귀·직접 테이블 접근 거부를 확인하고 모든 검증 데이터를 원복했다. 브라우저 두 테스트 화면에서 넘겨받기와 기존 화면 정지, 스테이지 강화 진입과 장비/강화/포션 탭 이동을 확인했다.
