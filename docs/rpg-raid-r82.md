# 4자리 코드 협동 레이드 r82

## 이용 흐름
모험 허브 → 같이 레이드 → 클라우드 캐릭터 선택 → 방 만들기/숫자 4자리 참가 → 2~4명 준비 → 방장 출발 → 전투 → 기여도 결과 → 재도전/이탈.

- 선행 0을 포함하는 0000~9999 문자열 코드. DB unique 제약, 충돌 재시도, 2시간 만료. 참가 시도 계정당 12회/분 제한(실패 요청도 유지).
- 구글 로그인 및 기존 원정대/클라우드 캐릭터 필요. 원정대 이름만 파티에 표시. 이메일과 저장 전체는 공유하지 않음.
- 한 계정 한 방, 방별 행 잠금으로 4명 정원·준비·방장·전투 상태 전환 직렬화. 종료 후 재도전은 새 runId 사용. 대기실 방장 30초 부재 시 접속자에게 이양, 이탈 방장은 남은 멤버에게 이양. 대기실 방장은 다른 참가자를 내보낼 수 있음.
- 700ms 요청/응답 동기화, 서버 250ms 고정 단계 시뮬레이션. 서버 시각·HP·피해·쿨다운·이동 속도·보상 판정. 브라우저는 입력만 전송. 일시 단절 후 동일 계정 resume. WebSocket 전용 전투 서버로 교체하기 쉽게 RPC 경계 분리.

## 첫 전투
폐광의 거신, 5분 제한, 인원과 입장 캐릭터 공격력으로 시작 체력 고정.
- 3초 균열 예고 → 해당 세로 구간 강타.
- 핵 노출 7초 피해 65% 증가.
- 수정 감옥 → 동료 공격으로 파괴, 12초 방치 시 피해.
- 25% 이하 기본 타격 간격 단축.
- 기본 공격 자동, 기술 자동/수동 전환, 터치 이동/방향키/WASD 및 1~4키.
- 근거리 3초 연속 구조, 이동 시 중단. 공용 부활 2회, 전멸 후 8초 내 부활 가능.

현재 레이드는 독립 밸런스: 저장된 레벨·전직·무기 슬롯 강화로 서버에서 입장 능력치 계산. 각 직업 기존 명칭과 아바타를 쓰고 근접/원거리/회복/방어 역할별 레이드 기술로 변환. 기존 싱글 사냥의 스킬 시뮬레이터 전체를 서버로 복제하지 않는다. 전투 중 클라우드/기기 세이브의 캐릭터 HP·골드·진행을 변경하지 않음.

## 기록과 보상
- 실제 피해만(잔여 HP 상한), 보호막 실제 흡수 및 실제 피해 감소만, 실제 체력 회복만 기록.
- 자기 방어/아군 보호 및 자기 회복/아군 회복 분리. 구조·수정 감옥 해제 횟수, 역할별 최다 기여 칭호.
- 정상 참가(공격·기술 5회 이상) 동일 보상: 한국 날짜 하루 3회 결정 30개. 이후 무보상 도움 참가, 실패 미차감.
- 결정은 별도 서버 지갑에 보관. 현재 상점/교환처는 아직 없으며 기존 골드 세이브와 합치지 않는다.
- runId/user PK 원장+지갑 잠금+방별 지급완료 플래그로 중복/동시 지급 방지.
- 게스트 혼자 연습은 3명 NPC라는 문구를 명시하고 서버 보상/기록 없이 실행. 연습 결과는 실제 멀티플레이 검증으로 간주하지 않음.

## 서버 접근
`server/raid/raid.sql`은 게임 프로젝트 fxkdlcqheyireuuykzzw에 적용. `rpg_raid` 비공개 스키마, 전 테이블 RLS 및 명시적 차단 정책, 테이블 직접 권한 없음. 공개 RPC는 SECURITY INVOKER로 내부 인증 검사 함수만 호출. 내부 조작 함수는 authenticated/anon에 실행 권한 없음. service_role 키는 클라이언트에 넣지 않음.

MCP 연결이 해당 inzae1 프로젝트 권한을 가지지 않아 기존 로그인된 SQL Editor에서 적용·검증. Supabase 스킬/RLS 문서 및 최신 changelog 확인. 기존 ranking/auth 관련 경고는 이번 작업 범위와 무관해 변경하지 않음. 신규 테이블은 직접 접근 차단을 유지.

## 검증
- `npm ci --prefix scripts/raid-test && node scripts/raid-test/verify.mjs`: PostgreSQL(PGlite)에서 인증 역할·코드 선행0·정원·방장·준비·재접속·서버 이동·쿨다운·실제 방어·초과회복·재도전·중복보상·하루3회·권한차단·시뮬레이션·실패 코드 시도 제한 검증.
- `server/raid/verify-live.sql`: 실제 서버의 2명 참가자 생성/참가/준비/시작/이동/권한 확인 PASS. 시험용 계정/세이브/방은 예외 하위 트랜잭션에서 모두 rollback.
- 기존 account/ranking/update/sword 검증 통과. 전투 중 업데이트는 종료 후로 미뤄 중간 새로고침을 방지. 실제 브라우저에서 연습 전투와 종료 통계·모바일 390×844 닫기 버튼/스크롤 확인.
- 아직 실제 이용자 4명이 서로 다른 기기에서 장시간 플레이하는 부하/지연 시험은 수행하지 않음. 현재 전투 동기화는 DB RPC 폴링이므로 대규모 동시 접속 전에 전용 전투 서버 전환 및 부하 검증이 필요.

공개 배포 후 로그인된 게임 화면에서 실제 4자리 코드 발급·준비 완료·시험 방 이탈을 확인. 첫 서버 연결도 성공, 콘솔 오류 없음. 시험용 방은 이탈해 원정대를 점유하지 않음.
