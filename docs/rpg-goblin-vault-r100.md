# 고블린 금고

모험 허브에서 구글 로그인·유효한 단일 접속권·클라우드 저장을 사용하는 Lv.30 이상 캐릭터를 선택한다. 선택 캐릭터의 골드 1,000G로 금고를 열며 계정 전체 하루 10회, 한국 시간 자정에 초기화한다.

|보상|확률|지급|순손익|
|---|---:|---:|---:|
|동전 주머니|40%|250G|−750G|
|은화 상자|30%|500G|−500G|
|본전 금고|20%|1,000G|0G|
|황금 금고|8%|2,500G|+1,500G|
|고블린 왕의 금고|2%|10,000G|+9,000G|

각 개봉은 독립 추첨이다. 평균 지급 850G, 평균 순소모 150G. 캐릭터를 바꿔도 계정 일일 횟수는 공유한다.

## 처리와 복구

서버 전용 함수에서 접속권과 소유권·레벨·골드·일일 한도·저장 revision을 검사한다. 서버 CSPRNG UUID의 무작위 32비트와 rejection sampling으로 0~9,999를 균등 추출한다. 보상 선택 입력은 받지 않는다.

계정별 transaction advisory lock으로 저장·접속권 이전과 직렬화하고, 차감·지급·클라우드 revision·접속권 revision·개봉 원장을 한 트랜잭션에 반영한다. user_id/request_id 기본키와 user_id/day/ordinal 고유키로 중복 지급과 한도 초과를 막는다. 같은 요청은 기존 결과와 현재 저장을 반환한다. 조회·재확인에는 추가 결제가 없다.

클라이언트는 개봉 전 진행을 저장하고 복구용 요청 ID를 기기에 남긴다. 서버 결과를 적용하는 동안 자동 저장을 보류하며, 네트워크 결과가 불명확하면 같은 요청을 조회한 후 최신 서버 저장을 적용한다. 과거 결과를 다시 확인해도 과거 payload로 롤백하지 않는다. 요청이 서버에 도착하지 않았으면 조회로 미결제 상태를 확인한다. 계정 변경·접속권 분실 시 기존 화면은 결과 적용을 중단한다.

## 연출과 모바일

기존 게임의 고블린 픽셀 스프라이트에 직접 그린 열쇠·금고·동전·왕관을 Canvas로 결합했다. 일반/황금/왕의 금고를 구분하며 지급 금액과 입장료 포함 손익을 함께 표시한다. GIF 파일을 새로 만든 작업은 아니다. 모바일 390×844에서 닫기·개봉·확률표를 검사했다.

## 적용·검증

server/session/sessions.sql이 먼저 설치되어 있어야 한다. server/vault/vault.sql 설치 후 server/vault/verify-live.sql로 실제 authenticated 역할의 원복 검증을 실행한다. 공개 RPC는 SECURITY INVOKER이며 실제 쓰기 함수와 원장은 비공개 스키마에 둔다. 원장 RLS 활성화 및 anon/authenticated 직접 읽기·쓰기, 보상 선택 helper 실행을 차단한다.

검증: verify-rpg-vault.mjs, raid-test/verify-vault.mjs. 10,000개 추첨 구간 전수 검사, 확률·기댓값, 한국 자정, 차감·지급·revision 정합성, 동시 동일 요청, 재요청·응답 유실 복구, 캐릭터 변경·소유권·레벨·골드·일일 한도·구형 접속권·직접 접근 거부를 검사한다. 운영 검증은 임시 사용자와 개봉 원장·재화·접속권 변경을 모두 ROLLBACK한다.
